# fudaut-datev-extf-mcp

**MIT-licensed Model Context Protocol (MCP) server for reading, deterministically validating, searching, balancing, and writing DATEV EXTF accounting batches (`Buchungsstapel`, Format Category 21).**

## English

`fudaut-datev-extf-mcp` connects MCP-compatible AI clients (Claude Code, Claude Desktop, Cursor, custom MCP hosts) to local **DATEV EXTF** booking batch files (`Buchungsstapel`, version `700`, category `21`). It runs strictly locally over `stdio`, makes zero network calls, performs exact integer-cent arithmetic, and enforces directory isolation and write-locks in the server process rather than relying on model prompts.

**Scope & Legal Boundary (German StBerG):** This software is a purely technical file-format utility for reading, syntax-checking, filtering, summing, and formatting EXTF CSV files (`§ 2 Abs. 3 Nr. 2 StBerG`). It provides **no tax advice** (*keine Steuerberatung*), **no account assignment** (*keine Kontierung*), and **no booking instructions** (*keine Buchungsanweisungen*). Account numbers (`Konto`, `Gegenkonto`), tax keys (`BU-Schlüssel`), and final booking confirmation always come from the operating company and its tax advisor (*Steuerberater*).

### Capabilities: Five MCP Tools

| Tool | Purpose | Modifies Disk |
|---|---|---|
| `stapel_pruefen` | Validates all 31 header fields and 125 booking columns against published DATEV regular expressions, character encoding, `CRLF` line endings, paired-column rules, fiscal-year dates, and posting period bounds; reports every finding with line number and field name | No (`readOnlyHint: true`) |
| `stapel_lesen` | Reads header metadata and paginated booking rows (up to 200 per call), resolving `TTMM` posting dates via fiscal-year start (`WJ-Beginn`) and amounts in integer cents (`umsatzCent`) | No (`readOnlyHint: true`) |
| `buchungen_suchen` | Filters bookings by account (`Konto` or `Gegenkonto`), case-insensitive text (`Buchungstext`, `Belegfeld 1/2`), ISO date range, cent amount range, and `S`/`H` side, returning debit/credit totals | No (`readOnlyHint: true`) |
| `konten_salden` | Computes per-account debit (`Soll`), credit (`Haben`), and net balance (`Saldo`) in integer cents (`Soll/Haben` applies to `Konto`, `Gegenkonto` is posted to the opposite side) | No (`readOnlyHint: true`) |
| `stapel_schreiben` | Writes a new `EXTF_*.csv` file (`Windows-1252`, `CRLF`, unlocked `Festschreibung = 0`) only if `DATEV_STAPEL_SCHREIBEN=1` is set and self-validation yields zero findings | Opt-in only (never overwrites) |

### Server-Enforced Safety Boundaries

1. **Single-Folder Isolation (`DATEV_STAPEL_ORDNER`):** Every path is resolved against `DATEV_STAPEL_ORDNER` (defaults to the current working directory). Parent traversal (`..`), outside absolute paths, and symlinks or Windows junctions pointing outside the root are rejected via `fs.realpathSync`. Files larger than 20 MB are refused. One client stays strictly one folder.
2. **Read-Only by Default:** `stapel_schreiben` is disabled unless the operator explicitly sets `DATEV_STAPEL_SCHREIBEN=1`. When enabled, it creates new `EXTF_*.csv` files exclusively (`wx` flag, never overwrites existing files) and always sets `Festschreibung = 0` (unlocked) so the tax advisor can review and edit.
3. **Atomic Pre-Write Validation:** Before `stapel_schreiben` writes a single byte to disk, the generated byte buffer is parsed back through `lesen()`. Any error or spec deviation aborts the write.
4. **Redacted Audit Log on `stderr`:** Every tool call writes one structured JSON line to `stderr` (`zeit`, `werkzeug`, `datei`, `ergebnis`). Booking texts and monetary amounts never appear in `stderr`, even when validation fails.
5. **Exact Integer-Cent Math:** All amounts are parsed and summed as integer cents (`umsatzCent`), avoiding IEEE-754 floating-point rounding drift.

### Deterministic Two-Tier Validation (`fehler` vs. `abweichung`)

`src/format.json` stores the field definitions and regular expressions for all **31 header fields** and **125 booking columns** extracted from the public DATEV format specification (`developer.datev.de`, retrieved `2026-10-13`) via `werkzeug/format-uebernehmen.py`. Where the upstream documentation provides a non-executable placeholder (`^[]$` on 5 reserved header fields), omits a duplicate currency regex (`WKZ Basisumsatz`), lists two variants (`Beleglink`), or specifies 4 digits where DATEV's own sample data uses 1 to 4 digits (`BU-Schlüssel`), the adjustment and rationale are explicitly recorded in `src/format.json` (`8` fields total).

Validation separates two severity levels:

- **`fehler` (Error):** The batch cannot be parsed reliably or contradicts itself (wrong column count, unclosed quotes, unreadable amount, `Soll/Haben` neither `S` nor `H`, `Konto` equals `Gegenkonto`, invalid calendar date such as Feb 29 in a non-leap year, posting date outside the batch period or fiscal year, or `UTF-16`/`UTF-32` encoding).
- **`abweichung` (Spec Deviation):** The batch is readable, but a populated field violates the published regex, a paired-column dependency (`PAARE`), `CRLF` line endings, or default `Windows-1252` encoding (`UTF-8` with or without BOM).

**Why two tiers matter in practice:** Tested against DATEV's own official sample file `EXTF_Buchungsstapel.csv` (`54` bookings, retrieved `2026-10-13`), this validator reports **`0` errors and `21` deviations**: `Erlöskonto (Anzahlungen)` set to `0` (`12x`), `Kurs` formatted as `0,830000` (`2x`), integer `Kost-Menge` (`2x`), `Umsatz` without decimals (`1x`), single-digit `Geschäftspartnerbank` (`1x`) without `SEPA-Mandatsreferenz` (`1x`), `Leistungsdatum` without `Datum Zuord. Steuerperiode` (`1x`), and `UTF-8` without BOM (`1x`). Collapsing both levels into one either rejects real-world reference files or hides fatal structural errors.

### Interoperability Note: Lexware Formatversion 12 vs. 13

- `stapel_schreiben` outputs DATEV `Formatkategorie 21` (`Buchungsstapel`) in **Formatversion 13** (`Versionsnummer 700`), matching DATEV's current specification for `DATEV Rechnungswesen` (`2026-10-13`).
- `stapel_lesen`, `buchungen_suchen`, and `konten_salden` also read older batches such as **Formatversion 12** (`ok: true`, surfaced in `stapel_pruefen` as a header `abweichung` against Formatversion 13).
- **Important for Lexware users:** According to Lexware FAQ `000002706` (verified `2026-11-02`), **Lexware buchhaltung** imports DATEV booking batches only up to **Formatversion 12.0**, not Formatversion 13. Always verify the supported EXTF format version or document import route of third-party accounting software before importing Formatversion 13 batches.

`npm test` executes **27 automated tests** (`26 PASS / 0 FAIL` out of the box, including `10` end-to-end `stdio` tests via `@modelcontextprotocol/client`; `27 PASS / 0 FAIL` when `DATEV_MUSTERDATEN` points to DATEV's official sample folder, omitted from this repository for copyright reasons). ```json

```json
  "mcpServers": {

      "args": ["-y", "github:iisakovbusiness-wq/fudaut-datev-extf-mcp"],
      "env": {

    }
  }
}
```

Or from a pinned local checkout (recommended for production folders):

```json

  "mcpServers": {
```

## Deutsch

`fudaut-datev-extf-mcp` ist ein lokal über `stdio` laufender Open-Source-MCP-Server (MIT-Lizenz) für **DATEV-Buchungsstapel im EXTF-Format** (`Versionsnummer 700`, `Formatkategorie 21`). Ein KI-Assistent mit MCP-Anschluss (Claude Code, Claude Desktop, Cursor) kann damit Buchungsstapel deterministisch prüfen, lesen, filtern, Kontensalden bilden und neue Stapel schreiben, ohne das Dateiformat raten zu müssen. Der Server baut keine Netzwerkverbindungen auf und rechnet ausschließlich ganzzahlig in Cent.

### Rechtliche Abgrenzung (StBerG) & Systemgrenze

Dieses Projekt ist ein **reines technisches Datenformat-Werkzeug** zur mechanischen Prüfung, Auswertung und Formatierung von EXTF-Dateien (`§ 2 Abs. 3 Nr. 2 StBerG`). Der Server leistet **keine Steuerberatung** (`§ 5 StBerG`), übernimmt **keine Belegkontierung** und erteilt **keine Buchungsanweisungen**. Sachkonten, Personenkonten, Steuerschlüssel (`BU-Schlüssel`) und die fachliche Freigabe stammen immer vom anwendenden Betrieb und seiner Steuerkanzlei. Geschriebene Stapel werden grundsätzlich **nicht festgeschrieben** (`Festschreibung = 0`), damit die Kanzlei vor der Verarbeitung prüfen und korrigieren kann.

### Die fünf MCP-Werkzeuge

| Werkzeug | Funktion | Schreibt auf Platte |
|---|---|---|
| `stapel_pruefen` | Prüft Kopfzeile (31 Felder) und jede Buchung (125 Spalten) gegen die veröffentlichte Formatbeschreibung, Zeichensatz, Zeilenende (`CRLF`), Paar-Abhängigkeiten, Wirtschaftsjahr und Stapelzeitraum; nennt jeden Befund mit Zeile und Feld | nein |
| `stapel_lesen` | Liest Kopfdaten und Buchungen seitenweise (bis zu 200 je Aufruf), löst das vierstellige Belegdatum (`TTMM`) über den Wirtschaftsjahresbeginn zum vollen ISO-Datum auf und liefert Umsätze in Cent | nein |
| `buchungen_suchen` | Filtert nach Konto (trifft Konto oder Gegenkonto), Textteil (`Buchungstext`, `Belegfeld 1/2`), Zeitraum, Betragsspanne in Cent und `S`/`H`-Kennzeichen inklusive Soll-/Habensummen | nein |
| `konten_salden` | Bildet je Konto Soll-Summe, Haben-Summe und Saldo in Cent (`Soll/Haben` gilt für `Konto`, das `Gegenkonto` wird auf der Gegenseite bebucht; Bruttoumsätze ohne Auflösung von Automatikkonten) | nein |
| `stapel_schreiben` | Erzeugt einen neuen Stapel (`EXTF_*.csv`, `Windows-1252`, `CRLF`, `Festschreibung = 0`) nach bestandener Selbstprüfung | ja, nur bei `DATEV_STAPEL_SCHREIBEN=1` |

### Fünf Sicherheitsgrenzen im Server statt im Sprachmodell

1. **Strikte Ordnergrenze (`DATEV_STAPEL_ORDNER`):** Jeder Dateipfad wird gegen `DATEV_STAPEL_ORDNER` aufgelöst (Standard: aktuelles Arbeitsverzeichnis). Zugriffe außerhalb, etwa über `..`, absolute Pfade oder symbolische Verknüpfungen und Windows-Junctions, weist der Server über `fs.realpathSync` ab. Dateien über 20 MB werden nicht geladen. Ein Mandant bleibt ein Ordner.
2. **Lesen als Standard:** `stapel_schreiben` ist abgeschaltet, solange `DATEV_STAPEL_SCHREIBEN=1` nicht ausdrücklich gesetzt ist. Auch dann legt der Server ausschließlich neue Dateien mit Präfix `EXTF_` an (`wx`-Flag, niemals Überschreiben) und setzt `Festschreibung = 0`.
3. **Keine unfertigen Dateien:** Vor dem Speichern durchläuft der erzeugte Byte-Puffer dieselbe `lesen()`-Prüfung. Sobald auch nur ein Fehler oder eine Abweichung vorliegt, wird nichts geschrieben.
4. **Datensparsames Protokoll auf `stderr`:** Jeder Werkzeugaufruf schreibt genau eine JSON-Zeile nach `stderr` (Zeitpunkt, Werkzeug, relativer Dateipfad, Kurzstatus). Buchungstexte und Beträge stehen dort nie, auch nicht im Fehlerfall.
5. **Rechnen in Cent:** Alle Beträge werden als ganze Zahlen (`umsatzCent`) verarbeitet, nie als Gleitkommazahlen.

### Zweistufige Formatprüfung (`fehler` und `abweichung`)

`src/format.json` enthält zu allen **31 Kopffeldern** und **125 Buchungsspalten** die regulären Ausdrücke aus der öffentlichen Formatbeschreibung der DATEV eG (`developer.datev.de`, abgerufen am `13.10.2026`), eingelesen über `werkzeug/format-uebernehmen.py`. An acht Stellen (fünf Leerfelder der Kopfzeile, `WKZ Basisumsatz`, `Beleglink`, `BU-Schlüssel`) ist ein nicht direkt ausführbarer oder gegenüber den DATEV-Musterdaten zu enger Ausdruck mit Begründung im Feld `angepasst` dokumentiert.

Die Prüfung trennt zwei Stufen:

- **`fehler`:** Der Stapel ist technisch nicht auswertbar oder widersprüchlich (falsche Spaltenzahl, ungeschlossenes Textfeld, unlesbarer Umsatz, Kennzeichen weder `S` noch `H`, `Konto` gleich `Gegenkonto`, nicht existentes Kalenderdatum, Belegdatum außerhalb von Zeitraum oder Wirtschaftsjahr, `UTF-16`/`UTF-32`).
- **`abweichung`:** Der Stapel ist lesbar, weicht aber bei einem gefüllten Feld vom veröffentlichten regulären Ausdruck, einer Feldpaar-Regel, dem Zeilenende `CRLF` oder dem Standard-Zeichensatz `Windows-1252` (`UTF-8` mit oder ohne Byte Order Mark) ab.

**Gemessener Hintergrund:** Die offizielle Musterdatei der DATEV eG (`EXTF_Buchungsstapel.csv`, `54` Buchungen, geprüft am `13.10.2026`) ergibt in dieser Prüfung **`0` Fehler und `21` Abweichungen**: `Erlöskonto (Anzahlungen)` mit Wert `0` (`12`), `Kurs` `0,830000` (`2`), ganzzahlige `Kost-Menge` (`2`), `Umsatz` ohne Nachkommastellen (`1`), einstellige `Geschäftspartnerbank` (`1`) ohne `SEPA-Mandatsreferenz` (`1`), `Leistungsdatum` ohne `Datum Zuord. Steuerperiode` (`1`) sowie Kodierung in `UTF-8` ohne Byte Order Mark (`1`). Beim `BU-Schlüssel` erlaubt der Server 1 bis 4 Ziffern, da 13 von 17 gefüllten Schlüsseln der Musterdatei weniger als vier Ziffern führen (mit wörtlich vier Ziffern wären es `34` Abweichungen).

Zwei häufige Fehlerquellen der Formatspezifikation berücksichtigt der Kern direkt:
- **Belegdatum (`TTMM`):** Das Kalenderjahr folgt aus dem Beginn des Wirtschaftsjahrs (Kopffeld 13), nicht aus dem Stapelzeitraum. Bei einem abweichenden Wirtschaftsjahr ab `01.07.` liegt der `31.12.` im ersten und der `02.01.` im folgenden Kalenderjahr.
- **Zeichensatz:** Standard ist `Windows-1252`. Unicode (`UTF-8`) akzeptiert DATEV laut Dokumentation nur mit Byte Order Mark und nur beim manuellen Import oder über `accounting:extf-files`.

### Wichtiger Hinweis zu Lexware (Formatversion 12 vs. 13)

- `stapel_schreiben` schreibt Buchungsstapel (`Formatkategorie 21`) in der aktuellen **Formatversion 13** (`Versionsnummer 700`, Stand `13.10.2026`).
- Ältere Stapel etwa in **Formatversion 12** werden von `stapel_lesen`, `buchungen_suchen` und `konten_salden` regulär gelesen (`ok: true`) und in `stapel_pruefen` transparent als Kopffeld-Abweichung gegenüber Formatversion 13 ausgewiesen.
- **Einschränkung bei Fremdprogrammen wie Lexware:** Laut Lexware-FAQ `000002706` (geprüft am `02.11.2026`) liest **Lexware buchhaltung** DATEV-Buchungsstapel nur bis **Formatversion 12.0** ein, nicht Formatversion 13. Prüfen Sie vor einem Import in Nicht-DATEV-Programme stets die dort unterstützte EXTF-Formatversion bzw. den vorgesehenen Beleg- oder Importweg.

### Was bewusst nicht enthalten ist

- **Direktübertragung an DATEV (`accounting:extf-files`):** Erfordert ein DATEV-Entwicklerkonto, Sandbox-Tests und eine Abnahme durch DATEV; dieser Server arbeitet rein dateibasiert.
- **Mehrplatz-Netzwerkbetrieb:** Ausgelegt auf lokales `stdio` pro Arbeitsplatz, kein HTTP-Server.
- **Weitere Formatkategorien:** Unterstützt wird ausschließlich der Buchungsstapel (`Formatkategorie 21`), nicht Stammdaten (`Debitoren/Kreditoren`), Kontenbeschriftungen oder wiederkehrende Buchungen.
- **`UTF-16` und `UTF-32`:** Werden deterministisch als Fehler abgewiesen, statt Zeichen zu raten.
- **Steuerlogik:** Automatikkonten und Steuerschlüssel werden nicht steuerlich aufgelöst; Salden zeigen Bruttoumsätze.

```text
server.json                     Metadaten nach Official MCP Registry Schema (2025-12-11)
```
